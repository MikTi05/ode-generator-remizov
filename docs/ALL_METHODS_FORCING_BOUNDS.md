# Аналитический сертификат forcing all_methods_v1

Модуль `all_methods_bounds.py` не меняет AST, генератор, загрузчик и данные.
Он использует проверенные `RemizovProblem` и metadata одного неизменённого
уравнения штатного загрузчика. Проверки schema, AST и конструкции переиспользуют
существующий decoder загрузчика. Строки формул не исполняются.

```python
from all_methods_bounds import certify_all_methods_forcing
from mc_solver import MCConfig, solve_monte_carlo

certificate = certify_all_methods_forcing(equation.remizov_problem, equation.metadata)
result = solve_monte_carlo(equation.remizov_problem, target_x, MCConfig(),
                          forcing_bound=certificate.forcing_bound)
```

`MCForcingBound` совместим с прежним API. Полный сертификат содержит версию,
SHA-256 serialized_ast с construction, компоненты оценки и способ округления.
Теорема относится к функциям, заданным этим AST; замена callable после загрузки
нарушает соответствие сертификата. Сеточные значения для доказательства не нужны.

## 1. Глобальные правила AST

Для узла u хранятся Uj >= sup_R |u^(j)|, j=0,1,2.
Все оценки ниже действуют на всей прямой, а не только внутри носителя решения.

| Примитив | U0 | U1 | U2 |
|---|---:|---:|---:|
| constant(k) | abs(k) | 0 | 0 |
| sin/cos(omega*x+phase) | 1 | abs(omega) | omega² |
| tanh(omega*x+phase) | 1 | abs(omega) | omega² |
| exp(-alpha*(x-mu)²) | 1 | sqrt(alpha) | 2*alpha |
| 1/(1+alpha*(x-mu)²) | 1 | sqrt(alpha) | 2*alpha |
| (x-mu)/sqrt(1+(x-mu)²) | 1 | 1 | 1 |

Обоснования: sup|tanh''|=4/(3*sqrt(3))<1. У гауссианы первая
производная имеет норму sqrt(2*alpha/e)<sqrt(alpha), вторая — 2*alpha.
У Lorentz нормы первой/второй производных равны соответственно
9*sqrt(alpha)/(8*sqrt(3))<sqrt(alpha) и 2*alpha.
Для saturating максимум второй производной 48/(25*sqrt(5))<1.
Сдвиги и фазы глобальных норм не меняют.

Для f(u) используются U1=M1*u1, U2=M2*u1²+M1*u2.

| Внешняя функция | M0 | M1 | M2 |
|---|---:|---:|---:|
| sin | 1 | 1 | 1 |
| cos | 1 | 1 | 1 |
| tanh | 1 | 1 | 1 |
| exp(-u²) | 1 | 1 | 2 |
| u/(1+u²) | 1/2 | 1 | 3/2 |

Для последней функции sup|f''|=(3+2*sqrt(2))/4<3/2; это получается
из стационарных точек u²=3±2*sqrt(2). Дополнительно используются безопасные
неравенства |sin u|,|tanh u|<=min(1,|u|), |u/(1+u²)|<=min(1/2,|u|),
|tanh'' u|<=2|u|, |(exp(-u²))'|<=2|u| и |(u/(1+u²))''|<=6|u|.

Для alpha*u+beta*v нормы ограничиваются суммами abs(alpha)*uj+abs(beta)*vj.
Для произведения:

    w0 = u0*v0
    w1 = u1*v0 + u0*v1
    w2 = u2*v0 + 2*u1*v1 + u0*v2

Эти правила покрывают все 14 разрешённых операций. Неизвестные операции
и непредставимые конечные границы отклоняются, сеточного fallback нет.

## 2. Bump и производные решения

Для |z|<1 положим u=1/(1-z²)>=1, phi=exp(1-u), вне интервала phi=0.
На границе все производные равны нулю. Внутри:

    phi'  = -2*z*u²*exp(1-u)
    phi'' = (4*u^4 - 12*u^3 + 6*u²)*exp(1-u)

|phi'|<=2*u²*exp(1-u)<=8/e<3, так как e>8/3.
Полином второй производной равен 4*u²*(u-3/2)²-3*u².
Если он отрицателен, его модуль <=6*u² и оценка <=24/e<9.
Если положителен, u>(3+sqrt(3))/2>3/2; при v=u-3/2>=0:

    phi'' <= 4*exp(-1/2)*(v^4+3*v^3+9*v²/4)*exp(-v)

Используем max(v^k*exp(-v))=k^k*exp(-k), e>=8/3,
exp(1/2)>=3/2. Получаем точную рациональную верхнюю границу:

    (8/3)*(256*(3/8)^4 + 81*(3/8)^3 + 9*(3/8)^2) = 1809/64.

Поэтому для bump((x-mu)/R): P0=1, P1=3/R, P2=1809/(64*R²).
Сдвиг mu произволен. Для y=s*bump*T_y с глобальными нормами Hj дерева T_y:

    Y0 = abs(s)*H0
    Y1 = abs(s)*(P1*H0 + H1)
    Y2 = abs(s)*(P2*H0 + 2*P1*H1 + H2).

## 3. Коэффициенты и forcing

Из существующей конструкции и |tanh v|<=min(1,sup|v|):

    A = a_mid + a_half*min(1, norm(T_a))
    B = b_scale*min(1, norm(T_b))
    C = c_scale*min(1, norm(T_c))
    G = A*Y2 + B*Y1 + (abs(lambda)+C)*Y0.

Это доказывает |g_R|<=G из g_R=-[a*y''+b*y'+(c_R-lambda)*y].
Вне компактного носителя forcing нулевой. Производные коэффициентов для
этой оценки не требуются: оператор имеет недивергентную форму a*y''+b*y'.

Данный C может быть точнее сертификата problem.c_abs_upper_bound, но MC
продолжает использовать прежний C из RemizovProblem. Коэффициенты, lambda
и постановка не меняются. Меняется только доказанная граница forcing.

## 4. Численная реализация верхних границ и хвоста

Положительные сложения, произведения и деления вычисляются как точные Fraction
от сохранённых float-параметров и округляются к float64 вверх. Корень sqrt(alpha)
проверяется точным сравнением квадратов Fraction и при необходимости округляется
вверх. Знаменатель R² не округляется вверх перед делением. Нулевые компоненты
остаются нулевыми. Переполнение сертификата приводит к BoundCertificationError.
Сертификат ограничивает математическую AST-функцию; ошибки численного evaluator
и MC рассматриваются отдельно.

Для G>0, delta=lambda-C_problem>0 хвост ограничен G/delta*exp(-delta*T).
MC использует нижнее float64-округление точной разности lambda-C и выбирает
T>=max(0,log(G/(delta*tail_eps))/delta). Decimal с 80 значащими цифрами и
односторонними соседями корректно округлённых ln/exp обеспечивает направленное
округление горизонта и границы хвоста. Корректность проверяется независимым
200-значным эталоном, в том числе при не представимой точно разности lambda-C.
Это устраняет обнаруженный случай F0002, где прежний float64 расчёт давал
0.00010000000000000009 при tail_eps=1e-4. Допуск не увеличивался.

Контролируется только хвост непрерывного представления. Временное смещение
и статистический шум остаются отдельными ошибками; total_error_certified=False.

## 5. Автоматическое подключение и практичность

CLI examples/solve_mc_equation.py автоматически выводит сертификат из metadata,
если пользователь не задал свой G. --uncertified-tail с явным T отключает вывод.
В diagnostics/compare_chernov.py MC получает этот сертификат автоматически;
в явном плане forcing_bound=null сохраняет неподтверждённый режим с явным T.
Прямой solve_monte_carlo по-прежнему принимает RemizovProblem и MCForcingBound:
в одном RemizovProblem AST нет, поэтому metadata передаются функции сертификата.

Правила треугольника не отслеживают алгебраические сокращения. Например,
s=2^40 и T_y=sin(x)-(1-2^-40)*sin(x) задают то же решение, что s=1,T_y=sin(x),
но сертификат может вырасти более чем в 10^12 раз. Это доказанный пример
консервативности, а не вывод из сеточного максимума.

Диагностика всех 20 задач сохраняет G, компоненты Yj, T, N, K*M*N и профиль
бюджета. Максимумы на двух сетках полного носителя — только smoke-наблюдения;
отношение G к sampled maximum не является доказанным коэффициентом запаса.
Расчёт стоимости не использует траектории. Время MC по числу шагов не угадывается:
стоимость AST и статистические требования могут сильно различаться.
