## Зависимости и границы переноса

- RK4 и его тесты используют только стандартную библиотеку Python.
- Product Integral и его тесты требуют NumPy и SciPy (`scipy.linalg.expm`).
- Тесты используют стандартный `unittest`; pytest не требуется.
- Проверенное окружение: Python 3.10.11, NumPy 2.2.6, SciPy 1.15.3.
  Это проверенные версии, а не установленные минимальные требования.

Обязательных локальных зависимостей времени выполнения у модулей нет.
Импорт `dataset_loader.CauchyProblem` в обоих модулях находится только внутри
`if TYPE_CHECKING` и при обычном выполнении не происходит.
Основные функции принимают коэффициенты непосредственно как Python-callable.

Обёртки `solve_problem_*` оставлены без изменений. При выполнении им нужен
объект с атрибутами `equation_id`, `a`, `b`, `c`, `g`, `x0`, `x1`, `y0`, `v0`;
проверки принадлежности к классу CauchyProblem нет. Сам класс в архив не входит.
Статическая проверка ссылки на CauchyProblem требует отсутствующий dataset_loader;
разрешение этой ссылки и адаптация типов к другому проекту здесь не выполнялись.

`dataset_loader.py` и CSV-интеграционные тесты `tests/test_rk4_pipeline.py`,
`tests/test_product_integral_pipeline.py` исключены: загрузчик импортирует
`screening_solver.py`, содержащий другой решатель и обработку датасета.
Они не нужны для прямого вызова двух методов и включённых модульных тестов.
Генераторы, датасеты, эксперименты, остальные методы и виртуальное окружение
в архив не включены.

## Использование

Оба метода решают линейную задачу Коши второго порядка:

    a(x) y'' + b(x) y' + c(x) y = g(x)
    y(x0) = y0, y'(x0) = v0

Требуются `x1 > x0`, положительное целое `n_steps` и положительный `a_min`
(по умолчанию 1e-3). Шаг фиксирован: h = (x1-x0)/n_steps.
Методы проверяют |a(x)| >= a_min в своих точках вычисления коэффициентов.

Распакуйте архив в отдельный каталог и выполните команды из его корня:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install numpy==2.2.6 scipy==1.15.3
.venv/bin/python -B -m unittest discover -s tests -v
```

Пример: y'' + y = 0, y(0)=0, y'(0)=1; точное решение y=sin(x).
Запускайте из корня распакованного архива тем же Python:

```python
import math
from rk4_solver import solve_rk4
from product_integral_solver import solve_product_integral_left_exponential

parameters = dict(
    a=lambda x: 1.0,
    b=lambda x: 0.0,
    c=lambda x: 1.0,
    g=lambda x: 0.0,
    x0=0.0, x1=1.0, y0=0.0, v0=1.0,
    n_steps=100,
)

for solve in (solve_rk4, solve_product_integral_left_exponential):
    result = solve(**parameters)
    if not result.success:
        raise RuntimeError(result.failure_reason)
    print(solve.__name__, result.y[-1], math.sin(1.0))
```

Оба результата содержат списки `x`, `y`, `dy`, флаг `success` и `failure_reason`.
При численном отказе возвращается накопленная траектория завершённых шагов
(для некорректного начального состояния поведение см. в исходных модулях).
RK4 для части некорректных входных параметров возбуждает ValueError;
Product Integral возвращает результат с `success=False`, `status` и `message`.

RK4 имеет четвёртый порядок сходимости. Конкретный Product Integral использует
Z=(y,y',1) и Z[k+1]=expm(h*B(x[k])) @ Z[k], где
B=[[0,1,0],[-c/a,-b/a,g/a],[0,0,0]]. Коэффициенты берутся на левом конце шага;
поздние множители действуют слева. При гладких переменных коэффициентах это
схема первого порядка, а при постоянной B она точна с учётом погрешностей
вычислений. Обе реализации используют фиксированный шаг без адаптации.
