# Общие инструкции для Claude Code и Codex

## Проект и контекст

`ode-generator-remizov` — самостоятельный Python-проект для исследования метода
Ремизова (аппроксимаций Чернова) на линейных ОДУ второго порядка с известным
точным решением. Основные части: генератор `all_methods_v1` в `src/`, безопасный
загрузчик `all_methods_dataset_loader.py`, `remizov_solver.py`, эталоны R1–R5,
экспериментальные драйверы в `diagnostics/` и сохранённые результаты в `results/`.

- В начале новой задачи используй [PROJECT_STATUS.md](PROJECT_STATUS.md) и
  необходимые файлы проекта для восстановления актуального контекста.
  README описывает запуск, `docs/` — форматы и прежние проверки; исходный код
  и сохранённые артефакты позволяют проверить факты. Планы не считай результатами.
- После существенных изменений проекта автоматически обновляй `PROJECT_STATUS.md`
  в рамках той же задачи: выполненная работа, подтверждённые результаты с источниками,
  принятые решения, оставшиеся проблемы и следующий шаг. Это относится и к новым
  экспериментальным результатам и важным исследовательским решениям.
  После мелких действий статус не обновляй; не переписывай всю историю и не удаляй
  полезную информацию. Устаревшие планы отмечай выполненными или заменёнными.
  При параллельной работе перечитывай статус перед записью и сохраняй дополнения других участников.
- Отвечай по-русски. В итогах указывай изменённые файлы, проверки и их результаты;
  различай подтверждённые факты, наблюдения и гипотезы.

## Работа над задачами

- Самостоятельно выполняй поставленную задачу до завершения, включая исправления,
  оптимизацию, изменения алгоритмов и тестов, если они входят в её объём.
  Дополнительные улучшения вне задачи предлагай отдельно.
- Следуй обычным разрешениям среды и ограничениям конкретной задачи. Не требуй
  подтверждения каждого шага и не вводи универсальных лимитов времени выполнения.
  Ресурсы эксперимента выбирай по его цели и оценке стоимости, фиксируя конфигурацию.
- Сохраняй существующие данные, результаты и возможность восстановить изменяемые
  версии. Для новых расчётов предпочитай новые пути; если изменение существующих
  артефактов необходимо, сначала обеспечь восстановление через версию или резервную
  копию. Не затрагивай соседний `../generator_DE` без задачи на его изменение.
- Перед изменением численной схемы кратко объясни обоснование и способ проверки.
  Ожидания тестов меняй на основании независимой проверки, а не подгонки под вывод.
  Для файлов `unchanged_mathematical_core` из `MIGRATION_MANIFEST.json` сохраняй
  прежнюю версию (Git либо `archive/core/`), согласуй `source_sha256` с новой версией и добавь запись с причиной,
  старым/новым хешами и способом восстановления в `core_sha256_history`.

## Математика и специальные правила

Перед работой с соответствующими компонентами прочитай и используй общие для
обоих агентов источники (Codex читает эти файлы по указанным путям):

- [.claude/rules/generator.md](.claude/rules/generator.md) — генератор, AST,
  сертификаты, воспроизводимость, версии данных и загрузка.
- [.claude/rules/remizov.md](.claude/rules/remizov.md) — решатель, постановка,
  оператор, погрешности и проверка изменений.
- [.claude/skills/experiment/SKILL.md](.claude/skills/experiment/SKILL.md) —
  планирование, запуск и анализ численных экспериментов и отчётов.

Ключевые особенности: `c = c_R − λ`, `g_R = −g`; в оператор Чернова входит `c_R`.
Решатель ищет ограниченное на всей ℝ решение `(λ − L)y = g_R`, а не решение
произвольной задачи Коши. `success` не гарантирует малую полную ошибку; разности
уточнений — индикаторы, `tail_eps` не является универсальной абсолютной границей.
Глобальные сертификаты аналитические; сеточные проверки не заменяют доказательства.

## Окружение, проверка и запись файлов

Команды выполняй из корня проекта, используй локальное `.venv`.
Проверенное окружение: Python 3.10.11; зависимости — `requirements.txt` и
`requirements-dev.txt`. `pytest.ini` добавляет корень в `pythonpath`.
Выбирай проверки по изменению; обычный набор без длительной регрессии R1:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B -m pytest -q -p no:cacheprovider tests \
  -k 'not test_r1_finite_chernoff_approximations_converge_toward_exact'
```

Полный pytest включает R1 при n=1,2,4,8; `verify_remizov_solver.py` — также n=16,32.
Они требуют больше вычислений; запускай их, когда это нужно для задачи.
Численную корректность проверяй по `E∞ = max|f − y_exact|` на фиксированной сетке
и при необходимости исследуй сходимость. Подробности — в математических правилах.

Задавай пути записи явно: генератор по умолчанию пишет в `data/` и перезаписывает
одноимённые файлы до полной валидации; `create_remizov_benchmark.py` пишет
`data/remizov_benchmark.csv`, а `verify_remizov_solver.py` — отчёт в `data/`.
Сохранённый малый набор находится в `data/generated/`; новые наборы и результаты
записывай в отдельный каталог, например `results/<тема>_<YYYY-MM-DD>[_<вариант>]/`.
