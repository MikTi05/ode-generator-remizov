# Вероятность точности + стоимость: ML-селектор, 2026-10-26

**Реализован и обучен исследовательский селектор с отдельными прогнозами
точности и времени Remizov и Monte Carlo.** Обучение не требует winner-labels;
использованы только реальные сохранённые ошибки/времена, прежние253 признака
и исходные семейные train-разделения. Численных solver/MC-вызовов **0**.
Прежние метки, численные результаты и модели сохранены.

К полноценному выбору приблизились архитектурно: обе альтернативы имеют
обученные p/time-heads, общую risk-policy и явную неопределённость. Проверенного
преимущества по вероятности точности MC и подтверждённой итоговой политики
пока нет. Предлагать текущий registry для надёжного применения нельзя.
Точное описание/API: [документ](../../docs/PROBABILISTIC_METHOD_SELECTOR.md).

## Как сохранить исходную научную цель

Цель — самый быстрый допустимый ответ с E_grid≤.01 на33 узлах. Для нового
MC-seed заранее неизвестно, попадёт ли он в допуск; исторический single-call
winner не делает ошибку детерминированной функцией коэффициентов.
Для профиля m прогнозируем p_m(x)=P(completed и E_grid≤.01|x,m) и типичную
полную warm-стоимость t_m(x). Выбираем минимальную прогнозируемую стоимость
при p≥q. **Порог q задаётся пользователем политики**, а не подбирается для
появления MC-класса. Сетка .5/.8/.95 фиксирована до fit только для диагностики.
Все ошибки по-прежнему сравниваются с .01; q описывает допустимый риск.

У Remizov истинная допустимость конкретного профиля детерминирована;
ML-p описывает неопределённость её прогноза на новых уравнениях. У MC-p
дополнительно имеет буквальный смысл вероятности по новому seed.
Ни прогноз p, ни bootstrap-разброс не являются сертификатом единичного ответа.
Строгую цель реализованного oracle нельзя гарантировать до вычисления MC;
вероятностная постановка явно учитывает этот неизбежный риск.

Обе альтернативы остаются действиями политики. Это не смена научной цели
на распознавание только риска Remizov. MC1 имеет собственные обученные
probability/cost модели; policy выбирает MC при подходящих оценках.
На реальных OOF-данных при q≥.5 она MC не выбрала — результат слабой
предсказуемости MC на доступной выборке, не отсутствие MC-действия в коде.
Для R128 также сохранён отдельный кандидат, чтобы не заявить преимущество MC
за счёт исключения более дешёвого точного R-профиля.

и weight n равен binomial negative log-likelihood этих исходов;
дополнительные синтетические строки/положительные примеры не создаются.
[Формула CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-classification).
Повтор исходных MC-seeds в timing-блоке даёт0 новых trials. Новые F0047
MC-seeds исключены из fit/calibration и оставлены для post-fit аудита.
Детерминированный R учитывается один раз на equation/profile.
MC0/MC2/x0/taper/mean4/20 старых final4096 не смешиваются с этими targets.

Full wall: MC median4 всех вызовов, в том числе неточных; R0 —35 одиночных
R256/3 R128, F0047 добавляет по одному median4 случаю. Старый solver-only
runtime не становится полным временем. Разные исторические cohorts
документированы; их перенос в один финальный timing context не доказан.
Cost-head учится log observed time; exp даёт приближение типичной стоимости,
не несмещённое математическое ожидание и не доказанный median4 для singleton R0.
[Реальные targets p](accuracy_targets.json), [targets времени](full_cost_targets.json),
[аудит источников](data_audit.json).

Обучено5 CatBoost-heads: p_R128,p_R256,p_MC1,t_R256,t_MC1.
Шестая голова t_R128 — эмпирическая константа по4 семействам с явным флагом
недостатка данных для регрессии. Это простой baseline времени, не точная
модель нового профиля. У всех голов point model плюс10 family-bootstrap
реплик; при resample без successes используется его реальная константа0.
Никакой искусственной балансировки нет.

Параметры фиксированы:120 деревьев,depth2,lr.05,l2=10,1 поток,seed2488,
bootstrap_type=No внутри CatBoost; внешнее resampling только по семействам.
3 CV-складки на40 paired train-семействах, в каждой holdout одно из3 семейств
с MC-success. Auxiliary R128 случаи исключают все held families.
Scaler fit только на соответствующем train. Original validation/test outcomes
не использовались в fit, настройке, калибровке или оценке. Test predictions нет.

## Что означает uncertainty

10/90 bootstrap quantiles — **некалиброванный разброс моделей**. Это не
confidence interval p(x), не CP-lower bound, не интервал случайного MC-ответа.
Текущий API возвращает все три профиля с p/time/spread и диагностическими
действиями, но production action=abstain/status=research_only.
Ограничение относится к готовности модели, исходная цель R/MC сохранена.
[Registry](registry.json), [serving-проверка](serving_check.json), [модели](models/).

Нужен независимый calibration/validation design; калибровка на обучающих
прогнозах даёт смещение. [Документация scikit-learn](https://scikit-learn.org/stable/modules/calibration.html).
Даже хорошая marginal calibration по семействам не даёт автоматически
pointwise-сертификата конкретного уравнения. Точность MC включает шум,
h-смещение и усечение; pointwise stderr solver не заменяет E_grid trials.

## Нужен ли прежний gate20+5

**Для обучения probability/cost подхода — нет.** Он относится к заявлению,
что прямой classifier научился распознавать MC-winner. Для новых голов нужны
реальные successes/failures и времена методов, а не выигрыш MC над R.
MC-success, который медленнее R, всё равно обучает p_MC; неточный вызов
обучает вероятность неуспеха и остаётся в стоимости. Победы не фабрикуются.
Показателен уже выполненный fit p_MC по7 реальным успехам без20 winner-семейств.

Снятие старого gate не устраняет нехватку данных. Требования новой постановки:
достаточная вариативность/поддержка outcomes на train-семействах, независимая
калибровка при выбранном q, валидация full cost и всей политики, затем frozen
семейный test. Сейчас successes MC лишь на3 семействах, validation outcomes0,
полных R128-time cases4. Новый универсальный gate в семействах не выводится:
размер зависит от q, требуемой точности вероятности и неоднородности данных.
Условие8 семей для time-regression в коде — инженерное, не статистическое.
Reliable-fastest .95 с59/59 успехами — другой большой эксперимент, не результат ML.

## Минимально необходимые данные и следующий эксперимент

Следующим нужен **заранее фиксированный held-family пакет**, а не ещё один
train seed, выбранный ради winner. Сохранены8 случайно выбранных исходных
validation-семейств: F0032,F0041,F0069,F0106,F0133,F0143,F0189,F0194;
по одному ID по стабильному хешу, без просмотра numerical outcomes/test.
Модели и q-сетка уже frozen. Для фиксированной пары R256/MC1:4+4 на ID,
**64 вызова**. Для исходного вопроса с допустимым R128 разумен полный
**R128/R256/MC1 пакет,96 вызовов**. Новые MC-seeds предложены до данных.
Предстартовый hash/seed/profile/work/resource/cost preflight и отдельное
разрешение ещё необходимы: **никакие вычисления из предложения не запускались**.
[Выбранные ID](NEXT_VALIDATION.json), [дизайн следующей проверки](VALIDATION_DESIGN.json).

Это первый диагностический пакет, не обещание достаточной calibration:
8 семейств и32 MC-trials могут не дать MC-success или узкого интервала p.
В таком случае показать отсутствие support и решить о расширении заранее,
а не добирать до удобного MC-winner. Для fit/calibration и оценки калибратора
нужны разные данные/корректный nested design; нельзя обучить calibrator и
проверить его на тех же8 случаях. Test остаётся закрытым до freeze всей политики.
Более широкая train-поддержка MC-success также может потребоваться для
предсказания p(x); отсутствие winner не препятствует собирать такие данные.
Сейчас нет оснований ожидать полноценного выбора после одного маленького пакета.
