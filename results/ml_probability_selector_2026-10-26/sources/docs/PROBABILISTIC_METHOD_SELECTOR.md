# Вероятностный выбор метода: исследовательская реализация v1

Эта версия реализует исходную цель выбора между Remizov и Monte Carlo через
отдельные прогнозы точности и стоимости. Контракт observed_fastest_v1 и его
старые артефакты сохранены. Новый schema — `risk_constrained_typical_cost_v1`.
Обе альтернативы реализованы как действия политики; `abstain` означает
недостаток оснований для решения при заданном ограничении риска.

## Что можно предсказывать до решения ОДУ

Для профиля m и входа x определим

\[
p_m(x)=P(\text{доставлен конечный ответ с }E_{grid}\le .01\mid x,\theta_m),
\qquad t_m(x)=\text{типичная полная warm-стоимость профиля}.
\]

MC-вероятность относится к новому независимому semantic seed и всему вектору
из33 значений, включая статистическую и дискретизационную ошибку. У Remizov
при фиксированных входе/профиле ошибка детерминирована: истинная допустимость
0/1. Его ML-вероятность описывает неопределённость прогноза допустимости на
новом уравнении; повторные детерминированные ответы не являются trials.

Реализованная политика минимизирует прогноз типичной стоимости среди методов
с прогнозируемой p≥q. **q обязателен и задаётся вызывающей стороной**.
В исследовании заранее выбраны q=.5/.8/.95 только для risk/coverage-кривой;
ни один не подбирался по результатам. Стоимость — прогноз log full warm wall,
затем exp; это приближение центральной стоимости, не доказанно несмещённое
матожидание времени. Будущая реализация строгой expected-cost задачи требует
отдельной модели распределения времени/смещения обратного преобразования.

Будущий строгий вариант использует калиброванную нижнюю границу вероятности
и интервалы стоимости. В текущих данных для этого нет независимой калибровки.
До запуска нельзя детерминированно узнать, какой MC-seed попадёт в E≤.01:
ни p=.95, ни ML-prediction не являются сертификатом каждого нового ответа.
Это явное описание риска исходной задачи, а не присвоение искусственного winner.

## Данные и обучение

Используются прежние253 input-only признака; ID/family/split/seed/error/exact/
runtime/status в X отсутствуют. Legacy pre_T/n-derived descriptors сохранены
с прежним смыслом, фактическими параметрами новых профилей они не объявляются.

Одна accuracy-строка — equation/profile с реальными k,n. Для MC P1/P2 это
четыре разных seed, для R — одна детерминированная ошибка. Модель CrossEntropy
получает target k/n и weight n:

\[
-n[(k/n)\log\hat p+(1-k/n)\log(1-\hat p)]
=-k\log\hat p-(n-k)\log(1-\hat p).
\]

Это binomial loss реальных исходов без генерации примеров или псевдометок.
Возможность fractional target/weights отражена в [документации CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-classification).
Bootstrap меняет веса целых семейств, не создаёт новых семейств/успехов.
Если resample не содержит successes, его прогноз — фактическая константа0;
искусственный положительный объект не добавляется.

| Профиль | Уравнений для p | Реальные trials | Точных | Уравнений с full wall |
|---|---:|---:|---:|---:|
| R128 | 103 | 103 | 75 | 4 |
| R256 | 40 | 40 | 33 | 36 |
| MC1 | 40 | 160 | 7 | 40 |

MC20 старого final4096 не смешивается с P1/P2; replay не увеличивает trials.
Новая группа F0047 из4 seeds исключена из fit/calibration и оставлена для
post-fit аудита. Она уже известна из истории, поэтому аудит не является
слепым prospective исследованием или новым семейным holdout.
R128 accuracy использует100 primary zero/commonT и3 R0; R256 —40 R0-матрицы.

Стоимость использует **только полное method wall**, без подстановки старого
solver-only runtime. Для MC —median4 включая неточные ответы; R0 предоставляет
одиночные full times35 R256 и3 R128, F0047 добавляет по одному4-repeat case.
Разные исторические timing cohorts документированы; равенство их контекстов
для финального межметодного выбора пока не подтверждено.

Модели: CatBoost CrossEntropy для p трёх профилей; CatBoost RMSE(log time)
для R256/MC1. У R128 time всего4 семейства — эмпирическая log-time константа
с флагом unsupported_for_regression. Порог8 семей для запуска time-regression
— инженерное ограничение прототипа, не доказательство статистической достаточности.

Все fit/scaler — original train.3 семейные CV-складки на40 paired cases,
по одному из3 MC-success семейств в holdout каждой складки. Auxiliary R128
cases используются только с исключением всех held families.
Фиксированы120 деревьев/depth2, seed2488,1 поток,10 family-bootstrap моделей
плюс point model на голову; гиперпараметры не подбирались.

## Неопределённость и API

Bootstrap10/90 quantiles — **некалиброванный разброс моделей**, не доверительные
границы истинного p(x), не MC predictive interval и не CP-lower bound.
Они могут не покрывать систематическую ошибку модели и шум времени.
`choose(...,robust=True)` блокирует решение при неоднозначных вероятностях,
порядке стоимости или недостатке R128-time данных. Его решения тоже исследовательские.
`choose(...,robust=False)` показывает point-estimate risk policy; при разнице
менее10% между MC и самым быстрым допустимым R предпочитает R.

`ProbabilisticSelector.select_method(coefficients, x_grid, metadata, q=...,
profile_context=..., timing_context=...)` проверяет схему/профили/контекст,
возвращает p/time/spread каждого изR128/R256/MC1 и обе диагностические политики.
При нынешнем registry action=abstain/status=research_only: deployment заблокирован
из-за отсутствия calibration/validation, а не из-за отсутствия MC-класса.
Новый алгоритм умеет выбирать MC при подтверждающих прогнозах — это проверяют
unit tests; готовность применять его к реальным задачам не заявляется.

Независимые данные нужны и для калибровки, и для проверки её результата;
калибровка на обучающих прогнозах даёт смещённую оценку вероятности.
См. [руководство scikit-learn](https://scikit-learn.org/stable/modules/calibration.html).
Калибровка на распределении семейств не превращается автоматически в гарантию
для каждого конкретного уравнения. Test используется один раз после freeze.

## Gate20+5 и достаточность данных

Gate20 train +5 validation **MC-winner семейств** остаётся условием прежнего
прямого классификатора observed-winner. Для factorized probability/cost модели
он не нужен: MC-успех полезен для p-head и при большей стоимости, а время
измеряется независимо от успеха. Отсутствие MC-winner не запрещает fit.

Новую постановку нельзя объявить готовой лишь потому, что gate снят. Нужны:

- реальные successes/failures MC на нескольких независимых семействах и
  достаточное число fresh trials для желаемой точности оценки p;
- original validation-данные для calibration/coverage и отдельной проверки
  политики при заранее выбранном q; при нуле MC-success support сообщается;
- сопоставимые full costs, охват R128 и учёт цензурирования/ошибок доставки;
- после freeze — семейный test без настройки по его результатам.

Универсального нового числа семейств нет. Размер зависит от q, желаемой
ширины интервала и неоднородности данных.4 MC-seed недостаточно для точной
индивидуальной вероятности.59/59 новых успехов для односторонней95% нижней
границы≥.95 — отдельная задача reliability из старого контракта, с ещё большим
бюджетом при множественных выводах; она здесь не запускалась.

Следующий пакет NEXT_VALIDATION.json:8 заранее выбранных original validation
семейств, по4 R256+4 MC1 =64 вызова, frozen модели/пороговая сетка.
Это первый диагностический пакет, не обещание полноценной calibration.
Для утверждения о самом быстром изR128/R256/MC1 добавить4 R128 на каждый ID:
**96 вызовов всего**. Все proposals execution_authorized=false, обязательны
отдельные numerical preflight/seed/budget фиксация и разрешение на запуск.
Повторять train F0005 только ради winner-класса теперь менее полезно,
чем проверить обобщение вероятностей на независимых семействах.
