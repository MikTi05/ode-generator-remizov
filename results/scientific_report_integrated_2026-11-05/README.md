## Сборка PDF

Из этого каталога в окружении с Tectonic:

```bash
TECTONIC_CACHE_DIR=/private/tmp/2488-tectonic-cache tectonic --keep-logs report.tex
```

В данной среде движок находится по пути
`/Applications/ChatGPT.app/Contents/Resources/plugins/openai-bundled/plugins/latex/bin/tectonic`.
Для первой сборки нужен доступ к стандартному пакету ресурсов Tectonic.
Использована версия 0.17.0. Unicode-ветка XeTeX/LuaTeX использует
Times New Roman и Courier New, при их отсутствии — DejaVu Serif/Mono;
соответствующие шрифты должны быть установлены. Путь pdfLaTeX сохраняет
исходные T2A/inputenc и Tempora на титульном листе; он в этой среде
не проверялся. Пагинация между движками/шрифтами может различаться.

PDF успешно собран: 49 страниц. Все страницы отрендерены и просмотрены,
новые таблицы и четыре графика проверены отдельно. `verify_pdf.py`
(зависимости `pypdf`, `pdfplumber`) проверяет встроенные шрифты,
отсутствие текста вне страницы, пустых страниц, неразрешённых ссылок,
команд и отсутствующих символов. Проверка прошла. Имеются сообщения
Underfull и один Overfull 1.82121 pt внутри физической страницы;
обрезания текста нет. Записи визуального контроля — `visual_review.json`.

Выполненные проверки сборки и просмотра фиксируются отдельно в
`layout_verification.json`; научная сверка — в `report_verification.json`
и `numeric_audit.json`. Архив `report_bundle.zip` предназначен для переноса
основного TeX, изображений и сопроводительных доказательств.

## Границы выводов и оставшиеся задачи

Полная MC E33 отсутствует: 62 нарушения следуют из нижней оценки,
938 исходов неизвестны. Три ответа Ремизова отсутствуют. Строгое
сравнение RK4 относится к 997 общим сохранённым задачам и тому же MC mean4.
Начальные условия RK4/PI точные, а R/MC решают глобальную постановку.
Скорость сходимости и универсальное превосходство RK4 не доказаны.

Cost60 даёт NO-GO для ML выбора RK4/PI в выполненной постановке:
PI не выигрывает, вся oracle-экономия обеспечена выбором N у RK4.
Boundary52 устраняет три выброса выше единицы, но оставляет 21 неточную
задачу; формальный NO-GO обусловлен тремя микроскопическими регрессиями
по строгому заранее заданному критерию. Пространственная устойчивость
и полные условия теоремы не сертифицированы, production не заменён.

Остаются полная сеточная MC-оценка, ошибка между узлами, контролируемое
уточнение сеток и окна, источники остаточной ошибки Ремизова, переносимость
времён/селекторов и стоимость поиска допустимой конфигурации. Эти задачи
не запускались при подготовке отчёта.
