Отчёт о проделанной работе
1. Математическая постановка
Рассматривается линейное дифференциальное уравнение второго порядка
a(x)y′′ + b(x)y′ + c(x)y= g(x).
Для применения метода Ремизова то же самое уравнение записывается в эквивалентной форме
a(x)y′′ + b(x)y′ + (cR(x)− λ)y=−gR(x),
где
cR(x) = c(x) + λ, gR(x) =−g(x).
Такая запись необходима для применения резольвентной формулы Ремизова. Само дифференциальное
уравнение при этом не изменяется.

Метод используется для нахождения ограниченного решения на всей действительной прямой, а не произ-

2. Почему первоначальная реализация работала медленно
Первоначальная реализация метода Ремизова оказалась вычислительно затратной.
Для вычисления интеграла использовался метод Гаусса–Лежандра. Во время работы программа посте-
пенно увеличивала число точек интегрирования и уменьшала шаг пространственной сетки.
После каждого изменения параметров решение рассчитывалось заново.
Основные вычислительные затраты были связаны со следующими операциями:
• многократным применением оператора Чернова;
• построением кубических сплайнов;
• повторным вычислением коэффициентов;
• обработкой больших пространственных сеток;
• повторным вычислением интеграла.
Таким образом, основная проблема заключалась в большом количестве повторных и дорогостоящих опе-
раций.
3. Оптимизация реализации
Для ускорения была адаптирована альтернативная реализация Chern.py, на основе которой создан модуль
chernov_solver.py.
Были внесены следующие изменения:
• Вместо изменения пространственной сетки во время расчёта используется фиксированный шаг.

• Метод Гаусса–Лежандра с повторными вычислениями заменён составным методом Симпсона.
• Коэффициенты уравнения и правая часть вычисляются заранее и затем используются повторно.
• Координаты точек, в которых необходимо вычислять значения функции, рассчитываются заранее для
каждого узла интегрирования.
• Вместо увеличения пространственной области используется фиксированный интервал. За его границами
значения функции определяются приближённым продолжением.
Математическая формула оператора Чернова сохранена, но изменились организация вычислений и про-
странственная дискретизация.

6. Возникшие проблемы
Недостаточная точность.
Из 126 неточных решений 113 имеют погрешность не выше 0.1. Однако несколько задач дали очень
большие ошибки.
Наиболее проблемными оказались уравнения высокой сложности с быстро колеблющимися коэффициен-
тами. В группе L4/oscillatory порог превышен для 34 из 50 задач.

Для отдельных уравнений наблюдался значительный рост промежуточных значений. Например, для
AMV1_F0141_S00 они достигали порядка 1045 на границах рабочего интервала.
Возможные причины больших погрешностей:
• недостаточное число применений оператора;
• ошибки пространственной интерполяции;
• влияние фиксированной области вычислений;
• погрешность численного интегрирования.
Пока нельзя однозначно определить, какая именно причина привела к большим ошибкам. Для этого
необходимо отдельно проверить результаты при изменении численных параметров.
Ошибки выполнения.
Три задачи не получили численного ответа, поскольку вычислительные процессы завершились до сохра-
нения результата. Подробная причина завершения не была записана.
Высокая вычислительная нагрузка.
При первоначальном массовом запуске одновременно работали восемь Python-процессов.
После обнаружения проблемы вычисления были организованы последовательно: с одним рабочим процес-
сом, контролем состояния компьютера, сохранением результатов и возможностью безопасной остановки.
7. Вывод
В ходе работы ускорена численная реализация метода Ремизова. На контрольных задачах новая версия
оказалась быстрее первоначальной в 1.30–34.63 раза.
