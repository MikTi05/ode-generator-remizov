1. Математическая постановка
Рассматривается линейное обыкновенное дифференциальное уравнение второго порядка
a(x)y′′(x) + b(x)y′(x) + c(x)y(x) = g(x), x ∈ R.
Здесь x — независимая переменная, y(x) — искомая функция, y′ и y′′ — её первая и вторая производные;
a(x), b(x), c(x) — заданные коэффициенты, g(x) — заданная правая часть. Ищется решение, ограниченное
на всей прямой R, а не произвольное решение задачи Коши с начальными условиями.
Для применения обоих методов исходное уравнение записывается в эквивалентном виде
(λ− L)y= gR, L= a(x)∂2
x + b(x)∂x + cR(x),
где ∂x означает дифференцирование по x, λ > 0 — выбранный параметр, cR(x) = c(x) + λ, gR(x) =−g(x).
Таким образом, L — дифференциальный оператор, а коэффициенты исходного уравнения не меняются.
Предполагается достаточная гладкость функций и условия
0 < a− ≤ a(x) ≤ a+, |b(x)| ≤ B, |cR(x)| ≤ C, λ > C.
Постоянные a− > 0 и a+ ограничивают коэффициент при y′′ снизу и сверху; B и C — известные верх-
ние границы модулей b и cR на всей прямой. Для созданных уравнений эти условия следуют из формул
коэффициентов, а не из проверки конечной сетки.
Точность оценивается двумя способами. На 33 равномерных точках xi =−1 + i/16, i = 0, . . . , 32, вычис-
ляется
E∞,33 = max
0≤i≤32 |ynum(xi)− yexact(xi)|,
где ynum — численное решение, yexact — известное точное решение, а E∞,33 — наибольшая абсолютная ошибка
среди этих 33 точек. Требуемый допуск: E∞,33 ≤ 0.01. Для вычисления только в центре сетки используется
E0 = |ynum(0)− yexact(0)|.
Почему их нельзя смешивать? При одном и том же численном ответе на всей сетке E0 ≤ E∞,33:
малая ошибка в точке x = 0 не исключает больших ошибок в остальных 32 точках. Поэтому доли успехов
одноточечных и сеточных экспериментов описывают разные требования к точности; сравнивать их как
одну метрику некорректно. Кроме того, E∞,33 не гарантирует такой же точности между узлами сетки.

4. Генерация уравнений и реальный пример
Для экспериментов создано 1000 уравнений: 200 семейств, содержащих по пять вариантов с одинаковой
структурой формул, но разными числовыми параметрами. Коэффициенты и точное решение строились из
комбинаций элементарных функций: синусов, косинусов, гиперболического тангенса, экспонент и рациональ-
ных выражений.
Четыре уровня сложности L1–L4 характеризуют строение этих формул, а не порядок дифференци-
ального уравнения. Для L1 допустимы простые деревья вычислений (обычно 1–2 уровня вложения и 3–7
элементов); для L2 — 2–3 уровня и 6–12 элементов; для L3 — 3–4 уровня и 10–18 элементов; для L4—
4–5 уровней и 14–24 элементов. Более высокие уровни допускают также более высокие частоты колебаний.
Приведённые размеры относятся к отдельному дереву формулы, а не к сумме всех коэффициентов.

5. Численные эксперименты
В первоначальной массовой серии Ремизова (n = 128, кубическая интерполяция с плавным затуханием за
краями окна) получено 997 конечных ответов из 1000; 871 ответ удовлетворяет допуску E∞,33 ≤ 0.01, ещё
126 — нет. Три запуска не сохранили численного результата из-за сбоя вычислительного процесса.
Исследование больших ошибок выявило влияние способа продолжения сплайна. На двух отдельных кон-
трольных задачах все вычислительные параметры оставили неизменными, а плавное затухание заменили
нулевым продолжением. Например, для F0141_S00 ошибка уменьшилась с 19704.50 до 0.01872. Причина ка-
тастрофически большой ошибки оказалась связана с численным продолжением функции вне рабочего окна,
а не с нарушением граничных условий исходного уравнения. Значение 0.01872 всё ещё выше допуска 0.01;
исправление не гарантирует нужной точности на всех уравнениях.
Ускорение оптимизированного Монте-Карло относительно исходной версии составило 3.71–8.31 раза на
пяти задачах. На одинаковых случайных приращениях расхождение траекторных вкладов не превысило
4· 10−15. Ускорение вычислений само по себе не уменьшает статистическую ошибку.

6. Машинное обучение
Задача машинного обучения — по заданным коэффициентам уравнения предсказать, будет ли
ошибка численного ответа не выше 0.01. Отдельно построены модели, оценивающие величину ошибки.
Предсказания относятся к конкретным вариантам алгоритмов с заранее установленными параметрами, а не
ко всем возможным настройкам метода.
Для каждого уравнения рассчитывались 253 входных признака:
• 128 значений функций: по 32 отсчёта четырёх известных функций a(x), b(x), cR(x) и gR(x);
• 56 статистик: для каждой из этих четырёх функций — минимум, максимум, среднее, стандартное
отклонение, среднеквадратичное значение, максимальный модуль, медиана, суммарное изменение сосед-
них значений, показатели первых и вторых разностей, доля отрицательных значений, смены знака и
доля высоких частот в спектре (всего 14 на функцию);
• 6 корреляций между парами этих четырёх функций;
• 48 структурных признаков: число узлов, глубина и количество операций каждого вида в деревьях
выражений для a, b, c (по 16 на коэффициент);
• 5 аналитических границ: нижняя и верхняя границы a, верхние границы |b| и |cR|, значение λ;
• 10 производных параметров: в частности, λ− C, расчётный горизонт интегрирования T , отношение
a+/a− и ориентировочные величины пространственных перемещений.
Отсчёты и статистики вычисляются по 256 входным узлам; это не те 33 точки, на которых проверяют ошибку
решения. Точное решение, ошибка, фактическое время работы, номер задачи и случайные seed
в признаках отсутствуют.
Обучались простая модель без признаков (Dummy), логистическая регрессия и CatBoost. Для прогноза
ошибки использовались также регрессионные модели. Из 1000 задач 700 составили обучающую часть (train),
150 — проверочную для выбора настроек (validation) и 150 — итоговую проверочную часть (test). Пять
задач одного структурного семейства никогда не попадали в разные части.

Первоначальная цель проекта — по коэффициентам уравнения выбрать метод, который быстрее
остальных достигает точности 0.01 на всей сетке. Её пока решить нельзя: сопоставимые измерения не

этому прототип честно сообщает, что выбор самого быстрого метода не установлен, вместо необоснованного
совета.
7. Вывод
Реализованы и исследованы два метода для одной резольвентной постановки линейного ОДУ второго по-
рядка. Создан набор из 1000 проверяемых уравнений, оптимизирован Монте-Карло и проведены прямые
сравнения точности и вычислительной стоимости. При испытанных настройках Ремизов существенно ча-
ще обеспечивал ошибку не выше 0.01 на всей сетке. Некоторые отдельные запуски MC были быстрее, но
гарантированная высокая вероятность достижения допуска пока не установлена.
Обученные ML-модели позволяют заранее оценивать риск того, что конкретный способ расчёта с за-
данными параметрами даст ошибку выше 0.01. При этом первоначальная задача автоматически выбирать
самый быстрый метод, который с высокой надёжностью обеспечивает этот допуск на 33 точках, пока не
решена. Для неё требуется лучше контролировать случайную и временную ошибку MC и получить больше
достоверных сравнений двух методов.
