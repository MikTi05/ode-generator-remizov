# Проверенные факты для научного отчёта

Это карточки фактов для автора отчёта на 5–7 страниц, не готовый научный
текст. Источники и ограничения указаны в SOURCES.md; исходные числа с полной
точностью — в SUPPORT/. Оговорки следует переносить в отчёт вместе с числами.

## F1. Постановка

- Ищется ограниченное на всей вещественной прямой решение линейного ОДУ
  второго порядка. Резольвента: `(lambda − L)y = g_R`, `c_R=c+lambda`, `g_R=−g`.
- Исследуются `ChernovSolver.solve` и MC на основе Фейнмана—Каца.
- Допуск — абсолютная ошибка 0,01. Одноточечная E0 и максимум на 33 узлах
  E∞33 различаются; E∞33 не является доказанным sup на всём интервале.
- Конечный ответ solver и достижение допуска — разные события. Ресурсный
  отказ не доказывает математическую неточность.

## F2. Реальный production-датасет

- Каталог `data/all_methods_v1_1000_2026-10-18/`, master seed 2488.
  200 семейств × 5 образцов = 1000 уравнений; 200 различных топологий.
- Четыре сложности L1–L4: по 250 уравнений / 50 семейств. Пять режимов:
  constant, slow_varying, moderate_varying, oscillatory, high_contrast —
  по 200 уравнений / 40 семейств. Всего 20 ячеек по 50 уравнений.
- Семейство фиксирует топологию четырёх AST a_raw, b_raw, c_raw, y_shape
  без числовых параметров. Пять экземпляров имеют разные числовые параметры.
- Whitelist из 14 операций: constant; sin/cos/tanh_affine; gaussian;
  lorentz; saturating; sin, cos, tanh; exp_neg_square; rational_saturate;
  lincomb; mul. Деревья ограниченные и гладкие. Деление и корень встречаются
  только внутри безопасных встроенных функций; произвольного eval нет.
- Для отдельной топологии интервалы depth/nodes и частотный cap:
  L1 (1–2 / 3–7 / 1,5), L2 (2–3 / 6–12 / 3),
  L3 (3–4 / 10–18 / 5), L4 (4–5 / 14–24 / 8).
  Это не число узлов суммы четырёх деревьев. В constant-режиме
  коэффициентные деревья специально вырождаются в константы.
- Коэффициенты: `a=A_mid+A_half*tanh(Ta)`, `b=B*tanh(Tb)`,
  `c_R=C*tanh(Tc)`, `lambda=C+gap`. Глобальные bounds следуют из конструкции.
  Режим меняет диапазоны коэффициентов и частот. Например, high_contrast:
  a_lower ∈ [0,5;0,9], a_upper ∈ [max(a_lower+0,8;2);3], B ∈ [1,5;5],
  C ∈ [1,5;4], gap ∈ [0,12;1,8].
- Сначала задаётся точное решение `y=s*bump((x−mu)/R)*Ty(x)` с компактным
  носителем, mu ∈ [−0,25;0,25], R ∈ [1,5;3]. Масштаб s нормирует сеточный
  max|y| к target_amplitude ∈ [0,5;1,5]. Затем аналитическими jets получают
  g=a*y''+b*y'+c*y. Конечных разностей для этих производных нет.
- ML-сетка: 256 узлов на [−1,1]; validation-сетка генератора: 2049;
  дополнительный smoke: 1025 узлов на [−10,10]. Это не целевая сетка solver33.
- Один штатный retry near_zero_solution у F0159/S00; итог без пропусков
  и точных символьных/числовых дублей. Ранее независимая регенерация из seed
  побайтово совпала с каноническими артефактами. Наблюдаемая residual=0,0
  проверяет manufactured-конструкцию, а не независимую трудность solver.
- Split назначен семействам до генерации экземпляров, стратифицирован:
  train 700 / 140 семейств, validation 150 / 30, test 150 / 30.
  Используются адресные SeedSequence/PCG64; отказ одной задачи не сдвигает остальные.

## F3. Массовый Ремизов1000: исторический профиль

- n=128, Q=513, dx=0,0125, padding=12, cubic/taper, legacy autoT,
  tail_eps=1e−8. Время интегрируется составной неравномерной формулой Симпсона.
- 1000 записей: 997 конечных ответов, 3 worker_exception с неизвестной
  математической ошибкой. Из 997 ответов 871 достиг E∞33≤0,01; 126 не достигли.
  Наблюдаемая доля 871/997=87,36%.
- При извлечении только узла x=0: 930/997=93,28%. Это другая метрика.
- Сумма solver wall по 997 ответам — 16620,74014 с. Первые 700 задач
  планировались с 8 внешними workers, последние 300 — с одним.
  Сумма не является календарным временем или изолированной CPU-стоимостью.
- Редкие катастрофические finite taper-ответы сохранены в targets.
  Их не удаляли и не заменяли исправленными zero-ответами при обучении.

## F4. Продолжение taper → zero

- Изолированные train-контроли joint_grid100 при прежнем T воспроизвели
  сохранённые ответы побитово. Менялся только boundary:
  F0141/S00: E∞33 19704,50191093 → 0,01871927854;
  F0184/S01: 444,58925464 → 0,05356807322.
- Катастрофические ошибки устранены на этих двух задачах, но обе ошибки
  всё ещё выше 0,01. Это не две краевые задачи ОДУ: менялось численное
  продолжение сплайна за рабочее окно.
- Основной grid100 затем использовал отдельный zero-профиль с общим G-T.
  Его нельзя выдавать за измерение чистого boundary-effect на всех 1000 задачах.

## F5. Оптимизация MC

- Value-only AST для a/b/c_R, совместное вычисление коэффициентов,
  аналитический jet y_shape для заданной g_R, переиспользование scratch.
  Numba, fastmath=False, один worker. Нет пространственной интерполяции.
  Схемы Эйлера—Маруямы, обе трапеции и адресные потоки RNG сохранены.
- На пяти задачах малого датасета: x=0, M=1024, h=1/128, общий T,
  три независимых seed, чередующийся порядок вызовов. Измеренное ускорение
  тёплого solve: **3,71–8,31×**. Подготовка и первая компиляция в него не входят.
- F0000: 0,230126 → 0,062021 с (3,7105×);
  F0002: 4,125900 → 0,730397 с (5,6488×);
  F0018: 6,102084 → 0,734547 с (8,3073×).
  Эти ID относятся к малому набору; совпадающий production-ID не доказывает идентичность.
- Подготовка AST: 0,379–1,781 мс. Первый импорт: 0,12985 с;
  JIT: 0,81707 с; сумма: 0,94692 с. Полная стоимость холодного вызова выше.
- Replay на одинаковых приращениях: максимальные расхождения path contribution
  4,00e−15, среднего 2,23e−16, stderr 6,94e−18, коэффициентов 4,27e−14.
  Это проверка эквивалентности на сохранённых случаях, не улучшение h-точности.
- **Уточнение вторичного источника:** прежний ml_research_closure/REPORT.md
  указывает 3,71–21,93×. Верхняя 21,93 не подтверждается первичной таблицей;
  использовать 3,71–8,31×. Старый обзор не переписывался.

## F6. MC1000 в x=0

- 4000/4000 завершений, 1000 уравнений, четыре seed × 1024 траектории,
  h_req=1/128, Numba, T по аналитическому G, tail_eps=1e−4.
- 1426/4000=35,65% отдельных seed достигли 0,01. Среднее четырёх seed
  (4096 путей на точку): 535/1000=53,5%. Четыре из четырёх успехов — у 56
  уравнений; хотя бы один — у 719. Четыре seed не подтверждают надёжность 95%.
- Сумма solver wall: 1633,24697 с; RSS 285,06 МиБ;
  12 138 684 416 обновлений траекторий. Загрузка/JIT/IO/monitoring — отдельно.
- 997 пар с Ремизовым проверены по expression_hash и наличию ровно одного
  узла x=0 (индекс16). Совместные исходы среднего MC:
  оба точны 526; только R точен 404; только MC точен 7; оба неточны 60.
  Семь MC-only исходов не являются надёжными метками более быстрого MC.
- Median E0: R 0,00118625, MC mean4 0,00918753;
  P90: 0,00760808 / 0,03890024; max: 842,08658 / 0,56976373.
- Exploratory separated quality labels: 60 в пользу R, 7 MC, 930 uncertain;
  в train лишь 44 R / 5 MC. Это метки близости среднего, не скорости.
- MC-время в x0 не сопоставлять как равнозначное с историческим временем R33.

## F7. Прямой общий grid100

- 100 train-уравнений, 88 семейств: 80 репрезентативных из 80 семейств
  (по 4 из каждой ячейки; вероятность включения 4/35, вес8,75)
  и 20 целевых stress-случаев. Выбор до новых расчётов; stress — по прежним
  train-ошибкам, стоимости и AST. Validation/test для настройки не использовались.
- R128/Q513/dx0,0125/padding12/cubic/zero; MC1024 на точку/seed,
  h_req=1/128, общий сертифицированный T, 33 узла [−1,1].
  Успех R: 66/80 representative, 7/20 stress. Первый MC: 0/80 и 0/20.
  Итог первого прохода: R-only73, neither27, both0, MC-only0.
- Для 12 выбранных случаев выполнены ещё три seed по заранее объявленному
  правилу. Появились два наблюдаемых успеха mean4 (F0005/S02, F0047/S00),
  оба при точном R. Итог: R-only71, both2, neither27, MC-only0.
  Повторы стоили 349,13 с; их отбор создаёт selection bias.
- Основной R: 1238,33 с; первый MC: 1833,88 с; четыре boundary-контроля:
  53,36 с. Всего 240 полных ответов и один прерванный запрос.
  Active wall 3561,57 с (59,36 мин), календарный с паузой 11406,99 с;
  сумма solver wall 3474,70 с, RSS 286,39 МиБ.
- Медианы прямого времени R/MC: 12,34 / 11,94 с;
  медианы E∞33: 0,002887 / 0,069753. Близкое время при 0/100 точных MC
  не означает равную эффективность.
- Одновременные normal error bands: 12 поддержанных неуспехов дискретного
  среднего, 88 uncertain, ни одного поддержанного успеха.
  Hoeffding: все 100 uncertain. Временное смещение отдельно не ограничено;
  reliable-fastest меток 0. Смешанные 73/100 не оценка для production1000.

## F10. Какие выводы допустимы

- Подтверждены измерения качества/стоимости фиксированных профилей,
  эквивалентность оптимизации на replay, снижение шума при M↑,
  улучшение R на пяти задачах при n↑, информативные quality-surrogate
  относительно constant baseline на сохранённом holdout.
- Не подтверждены оптимальный выбор solver, высоконадёжный MC-grid профиль,
  универсальный порядок h/n, полная декомпозиция ошибки, перенос R2565/5
  на1000, перенос taper-модели наzero, универсальное превосходство Ремизова.
- Для первоначальной цели нужны единые профили/grid/hardware, прямые полные
  стоимости, контроль h-bias и одновременной статистики MC, достаточные оба
  класса надёжных исходов, семейные calibration/holdout данные zero
  и новый prospective family test. Это перечень недостающих данных,
  не новый запуск в текущем задании.
