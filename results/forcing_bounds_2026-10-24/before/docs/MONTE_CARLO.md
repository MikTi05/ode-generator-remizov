# Монте-Карло Фейнмана — Каца

`mc_solver.py` принимает существующий `RemizovProblem` и решает глобальную
задачу `(lambda - (a*d2 + b*d + c_R)) y = g_R`, без начальных условий.
Предполагается корректная невзрывающаяся диффузия и нужная регулярность.
Для генератора это обеспечивается гладкой ограниченной конструкцией и a>0;
произвольные Python-функции программа математически не сертифицирует.

Схема сохранена из предоставленного MC: Эйлер — Маруяма с дисперсией 2*a*h,
трапеция для интеграла потенциала и для интеграла forcing, среднее независимых
траекторий. Снимок источников и хеши: `comparison_inputs/monte_carlo/`.
Временной порядок для произвольных переменных коэффициентов не заявляется.

```python
from mc_solver import MCConfig, MCForcingBound, solve_monte_carlo

# equation загружено штатным all_methods_dataset_loader.
result = solve_monte_carlo(equation.remizov_problem, target_x,
    MCConfig(M=20000, dt=.005, T=8., seed=2488))
```

Загрузчик фактически предоставляет векторные функции a,b,c_R,g_R.
MC также распространяет скалярные значения констант на форму массива;
скалярный fallback с циклом по координатам не используется.

## Глобальные границы и горизонт

Сертификаты коэффициентов берутся из RemizovProblem: `analytic/all_real_x`,
0<a_lower<=a<=a_upper, |b|<=B, |c_R|<=C и lambda>C.
Значения проверяются против сертификатов на посещённых точках, но это не
доказывает их глобальность и не проверяет гладкость произвольного callable.
Границы не оцениваются на пространственной сетке.

Если известен доказанный G>=sup|g_R|, передайте
`MCForcingBound(G, source="аналитическое обоснование")`. Тогда при T=None:

    gap = lambda-C
    T = max(0, (log(G)-log(gap)-log(tail_eps))/gap)
    tail_error_bound = G/gap * exp(-gap*T)

Для G=0 горизонт равен нулю. Расчёт логарифмический; положительный горизонт
округляется вверх на один float64-шаг. Оценка относится только к хвосту
непрерывной формулы Фейнмана — Каца, не к дискретизации и не к выборочному шуму.
Граница — аналитическая формула, вычисленная в float64, не интервальная арифметика.

В all_methods_v1 отдельного численного сертификата G нет. Автоматического
вывода G из AST в этой интеграции нет. Без сертификата нужен явный T;
`tail_error_bound` и `tail_tolerance_met` остаются None. Это допускает
диагностический расчёт, но не гарантирует малость хвоста. При T=None без G
возвращается `missing_forcing_bound` до моделирования.

Явный T не обходит проверку lambda>C. Если T задан с G, граница хвоста
вычисляется, даже если она превышает tail_eps; `tail_tolerance_met` это отражает.
Не следует использовать sampled maximum forcing как сертификат.

## Результат и ошибки

`MCResult` содержит x,f, stderr, полуширины ci95 и границы интервалов,
фактические M/h/T/N, выполненную работу, seed, адреса потоков и время всего
вызова с отдельной подготовкой. Производная не вычисляется.

`ci95 = 1.96*stderr` — приближённый точечный нормальный интервал для среднего
дискретного усечённого вклада. Он не включает ошибку h или хвост T и не даёт
совместного покрытия всей сетки. Для малых M и сложного распределения
номинальное покрытие не гарантировано. M>=2 необходимо, но недостаточно для ЦПТ.

Дисперсия считается по центрированным пакетным моментам с объединением Chan.
`paths_for_tolerance` — только pilot-оценка общего числа траекторий по
статистическому бюджету. Она не гарантирует общую точность и отвергает нулевой
pilot stderr, не вводя искусственного порога для дисперсии.

`success` означает завершение конечного расчёта. `total_error_certified=False`,
`discretization_error_bound=None` даже при наличии границы хвоста. Для проверки
точности вычисляйте E∞=max|f-y_exact| на заранее заданной сетке после решения.
При отказе f и все статистические массивы пусты; x, выполненная работа,
число завершённых выборок и причина отказа сохранены. T=0 — точный нулевой
усечённый интеграл без моделирования, completed_paths=0.

Ошибки параметров вызывают ValueError. Штатные причины: invalid_remizov_conditions,
missing_forcing_bound, nonpositive_diffusion, certified_bound_violation,
nonfinite_coefficient, invalid_coefficient, coefficient_evaluation_failure,
nonfinite_state, nonfinite_statistics, numerical_overflow, numerical_underflow, insufficient_samples,
work_limit_exceeded, time_limit_exceeded.

## Воспроизводимость и ресурсы

PCG64/SeedSequence адресует поток по seed, problem_id, координате и stream_id;
одна точка повторяется независимо от присутствия других точек. seed=None
сохраняет выбранную энтропию для последующего воспроизведения. Глобальный RNG
NumPy не используется. Размер chunk — часть конфигурации: его изменение
меняет распределение случайных чисел между траекториями. Побитовая
воспроизводимость между разными версиями NumPy не обещается.

N=ceil(T/dt), фактический h<=dt. До выделения рабочих массивов проверяются
max_steps, max_path_steps для всех точек и max_batch_paths. Память собственных
массивов O(chunk), работа O(K*M*N), без хранения истории траекторий.
Производительность и память AST/callable зависят от входной функции.
max_runtime_seconds проверяется между шагами: блокирующий callable требует
внешнего watchdog, а max_batch_paths не является жёстким лимитом RSS процесса.
Лимиты конфигурации можно явно менять под эксперимент.
Положительный T использует минимум один шаг даже при underflow T/dt;
непредставимый в float64 полушаг вызывает отказ numerical_underflow.

## CLI без записи файлов

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B examples/solve_mc_equation.py \
  --equation-id AMV1_F0000_S00 --points 33 --M 2000 --dt .02 --T 4 \
  --seed 2488 --max-runtime-seconds 30
```

CLI печатает JSON со всем результатом, конфигурацией, exact и фактической
ошибкой. Код выхода 0 означает численный успех, 1 — штатный отказ.
Для автоматического горизонта нужны вместе --g-bound и --g-bound-source;
ответственность за аналитическое доказательство границы остаётся у вызывающего.
Входные CSV/JSONL по умолчанию читаются из data/generated, без изменения.

`diagnostics/compare_chernov.py` принимает в явном плане метод `monte_carlo`
с MCConfig и необязательным `forcing_bound` (поля MCForcingBound). Используются
существующие worker, watchdog, RSS, хеширование и запись всех попыток.
Встроены аналитические MC_constant и MC_gaussian с доказанными G=1 и G=4.
Прежние ветки Ремизова/Chern сохранены. Production batch и ML не подключались.
