## План, постановка и единственный запуск

План записан **до численного расчёта**: [plan.json](plan.json).
Исходный набор: `data/all_methods_v1_1000_2026-10-18/`, CSV SHA-256:
`940d6c10a8cdd0933bb5c663c681efd39bac5ed450ea37cbb95be1ca481136ad`.
Безопасный загрузчик — существующий `load_all_methods_equations`.

Для каждого метода и каждого уравнения неизменно:

```text
x0=-1, x1=1, n_steps=128, h=1/64, a_min=0.001
129 узлов; x[64] == 0.0
исходные a,b,c,g; сохранённые y0,v0
E0 = abs(y_numeric[64] - y_exact(0))
accuracy_met = E0 <= 0.05
```

Вызывались неизменённые публичные обёртки из `src.numerical_methods`.
Начальные условия не выводились заново из exact. Подмены c на c_R и g на g_R
нет. Точный ответ запрашивается драйвером только после возврата solver для
оценки ошибки; стандартная валидация manufactured-данных внутри прежнего
загрузчика сохранена. В forcing g используется исходное представление датасета.

Выполнены **ровно 2000 новых production-вызовов**, по 1000 на каждый метод;
других шагов N, адаптации, интерполяции, уточнений и подбора параметров не было.
Ремизов и MC не пересчитывались. Штатные unit-тесты известных аналитических
примеров сохранены; они не являются дополнительной production-серией.

Дополнительно из каждой полной траектории сохранена E_inf на фиксированных
33 узлах `linspace(-1,1,33)`, соответствующих каждому четвёртому узлу траектории,
и E_inf / sampled max|exact|. Это вспомогательные метрики, не критерий winner
и не непрерывные верхние границы ошибки.

Исходный проект уже содержал незакоммиченную интеграцию предыдущей задачи.

## Сохранение и продолжение

Каждая задача хранится отдельно:
`records/rk4/<equation_id>.json` и
`records/product_integral/<equation_id>.json`.
Запись содержит идентичность датасета/AST/семейства, SHA плана, исходные НУ,
конфигурацию, полный dataclass результата, статус, пригодность, y(0), exact(0),
E0, accuracy_met, время solver, ресурсный показатель и собственную контрольную
сумму. Данные публикуются атомарно после fsync, существующие файлы не заменяются.
Исключение одного solver записывается отдельно и не останавливает следующие
задачи. Незавершённая неопубликованная задача может быть выполнена при resume;
все корректные терминальные записи, включая отказы, пропускаются.
Повреждённая запись вызывает остановку с сохранением исходного файла.
Одновременный запуск контроллеров блокируется файловой блокировкой.

[Execution log](execution.log) фиксирует завершение 2000 задач.
Проверка resume повторно прочитала и проверила все 2000 записей: **0 новых
вызовов**, 2000 пропусков. Байты, размеры и mtime всех записей сохранились:
[resume_verification.json](resume_verification.json), [resume.log](resume.log).
Это техническая проверка продолжения, не повторный численный эксперимент.

Ресурсы: один процесс, NumPy/SciPy BLAS/OpenMP по одному потоку;
Python 3.10.11, NumPy 2.2.6, SciPy 1.15.3. Основной цикл с расчётом, метриками
и атомарной записью занял **308.432394 с**, без начальной загрузки/валидации.
Пиковый RSS основного процесса **219.578125 МиБ**. Проверены фактические
**512000 RK4 RHS-evaluations** и **128000 PI expm-evaluations**.
Искусственных внешних ограничений времени/памяти не вводилось.
Время каждого нового solver измерено вокруг публичной обёртки, без вычисления
exact/ошибок и записи. Старое время R — result.runtime_seconds, время MC mean4 —
сумма runtime_seconds четырёх сохранённых запусков. Различные эпохи/границы
таймеров не позволяют трактовать эти значения как новый честный speed benchmark.
Время **никогда** не входит в разметку.

## Старые источники и критерий winner

Ремизов — массовая серия `chernov_solve1000_2026-10-18/solutions`, действующий
профиль R128 с cubic/taper. Monte Carlo — четыре исходных независимых seed
202610250101…202610250104 серии `mc1000_x0_2026-10-25/attempts`, M=1024,
dt=1/128. Среднее вычислено **до** абсолютной ошибки:
`E_MC = abs(mean(f_seed0,f_seed1,f_seed2,f_seed3)-exact0)`.
Это прежний агрегат четырёх ответов, не новый одиночный запуск MC4096.
Численные ответы и E0 сверены с действующим mean4 coverage.csv.

Winner — минимум реальной конечной E0 среди пригодных результатов.
Заранее заданный порядок точных равенств:
**remizov → monte_carlo → rk4 → product_integral**.
Сравнение неокруглённое, без tolerance и без времени. Точных равенств на общем
пересечении **0**. В coverage1000 и incomplete-таблице best_method означает
лучший доступный ответ и имеет scope `available_only`; эти строки не попадают
в ML-таблицу четырёх методов.

## Воспроизведение

Новый каталог следует готовить с новым именем. `prepare` сохраняет конфигурацию
и контрольные суммы до вызовов solver; `run` продолжает существующую серию.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  diagnostics/run_rk4_product_integral_mass.py prepare --out results/NEW_DIRECTORY

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  diagnostics/run_rk4_product_integral_mass.py run --out results/NEW_DIRECTORY

# Технический resume: все сохранённые задачи пропускаются, новых вызовов 0.
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  diagnostics/run_rk4_product_integral_mass.py run --out results/NEW_DIRECTORY

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  diagnostics/report_four_method_accuracy.py --out results/NEW_DIRECTORY

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B \
  diagnostics/verify_four_method_accuracy.py --out results/NEW_DIRECTORY
```

Команды здесь — инструкция, не дополнительный запуск. Verifier также требует
наличия сессии технической проверки resume с нулём новых вызовов. Экспортёр
создаёт новый release-каталог и не заменяет старые таблицы.

Созданы четыре новых диагностических модуля: `four_method_common.py`,
`run_rk4_product_integral_mass.py`, `report_four_method_accuracy.py`,
`verify_four_method_accuracy.py`; новый тест — `tests/test_four_method_accuracy.py`.
Из прежних файлов изменён только статус. Все результаты этой задачи — внутри
данного отдельного каталога.

   текущем manufactured-датасете и согласованных начальных условиях.

   различать методы. Постоянный выбор RK4 уже совпадает со всеми 997 winner-метками.

   датасета и бюджета; новая ML-модель не обучалась.
