# ode-generator-remizov

Независимый локальный проект: существующий генератор `all_methods_v1`,
метод Ремизова/аппроксимация Чернова, безопасная загрузка и проверки.
Математические файлы генератора, выражений и решателя перенесены без
изменений; список файлов и исходные SHA-256 — в `MIGRATION_MANIFEST.json`.

## Установка

Команды выполняются из корня этого проекта. Проверочное исходное окружение:
Python 3.10.11. Зависимости зафиксированы по его фактическим версиям.

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

NumPy и SciPy нужны рабочим компонентам. SymPy нужен проверочным задачам
Ремизова и независимым тестам аналитических производных; pytest — тестам.
Старое виртуальное окружение и файлы исходного проекта не требуются.

## Небольшой датасет: 20 уравнений

Сохранённый проверочный набор уже находится в `data/generated/`. Пример ниже
создаёт отдельный набор в `data/generated_example/`; если этот путь уже существует,
выберите новый и используйте его во всех командах. Для работы с сохранённым набором
генерация не нужна: укажите `data/generated/` при загрузке или валидации.

```bash
python generate_all_methods_dataset_v1.py \
  --output-dir data/generated_example --seed 2488 \
  --n-families 20 --samples-per-family 1 \
  --ml-grid-size 32 --validation-grid-size 257

python validate_all_methods_dataset_v1.py --input-dir data/generated_example
```

Число семейств должно быть кратно 20. Нормировка зависит от выбранной
validation-сетки; указанные параметры создают небольшой проверочный набор,
а стандартные параметры генератора сохранены. Первая команда автоматически
выполняет полную проверку записанных артефактов, включая регенерацию.
Запуск без параметров генерирует 1000 уравнений: это отдельная большая проверка.

CSV содержит описания формул и начальные условия. Для восстановления
исполняемых функций, сертификатов и точного решения нужен соответствующий
`all_methods_equations_v1_metadata.jsonl`. Все четыре артефакта, включая
`_ml.npz` и отчёт, нужны полному валидатору. Имена и формат v1 сохранены;
моделей машинного обучения в проекте нет.

## Загрузка и небольшой расчёт Ремизова

```bash
python examples/solve_generated_equation.py --input-dir data/generated_example \
  --equation-id AMV1_F0005_S00 --n 1 --points 33 --verification-budget
```

Опция `--verification-budget` выбирает существующий фиксированный бюджет
`make_verification_config`: пределы уточнений 8 и 5. Без неё используются
неизменённые библиотечные настройки `RemizovConfig` (4 и 4). Автоматического
увеличения бюджета и повторных попыток нет. JSON содержит статус, причину
отказа, фактическую максимальную абсолютную ошибку относительно `y_exact`
и настройки расчёта. При отказе ошибка равна `null`, exit code — 1.
В проверочном наборе с указанным seed F0000 при этом бюджете
возвращает `quadrature_not_converged`; F0005 завершается успешно,
но при n=1 имеет большую ошибку около 3.043. Это отдельные результаты
одного метода с одинаковыми настройками, без повторных попыток.

API: `load_all_methods_equations(csv_path, metadata_path)` возвращает
`AllMethodsEquation` с `remizov_problem`, `cauchy_problem`, `y_exact`,
`dy_exact`, `d2y_exact` и metadata. Передайте `remizov_problem` напрямую в
`solve_remizov`, а `result.f` сравнивайте с `y_exact(result.x)`.
Загрузка одного ID сейчас проверяет весь комплект CSV/JSONL.

Ремизов вычисляет глобальную резольвентную аппроксимацию и не принимает
произвольные `y0`, `v0`. У этого генератора начальные условия получены из
того же изготовленного точного решения. Знаки: `c = c_R - lambda`,
`g_R = -g`; загрузчик уже выполняет это согласование.

Успех вычислений не гарантирует малую полную ошибку при конечном `n`.
Квадратурные и пространственные оценки — диагностические разности между
уровнями уточнения. Формула усечения сохранена; она не учитывает норму
правой части, поэтому универсальная абсолютная интерпретация `tail_eps`
требует отдельного математического аудита. Допустимая задача может вернуть
штатный отказ по сходимости или лимиту рабочей сетки.

## Тесты

Набор для локальной проверки без исследования сходимости n=1,2,4,8:

```bash
python -m pytest -q tests \
  -k 'not test_r1_finite_chernoff_approximations_converge_toward_exact'
```

Сохраняются существующие тесты генератора, независимых производных,
сертификатов, оператора, ручных эталонов R1 и R1–R5 при n=1. Один
генераторный тест проверяет план 200 семейств с одной выборкой и малыми
сетками; полная генерация 1000 уравнений при этом не выполняется.
Дополнительные тесты проверяют загрузку повреждённых файлов,
самостоятельность импортов и путь генератор → загрузчик → Ремизов.

Полный набор `python -m pytest -q tests` включает сохранённую регрессию
сходимости до n=8. `verify_remizov_solver.py` запускает более длительные
исследования, включая n=16,32; для первоначальной проверки его не запускать.
R1–R5 в `data/remizov_benchmark.csv` — проверочные задачи одного метода.

Математическое описание: [docs/ALL_METHODS_DATASET_V1.md](docs/ALL_METHODS_DATASET_V1.md).
Отчёт первоначальной проверки: [docs/LOCAL_VERIFICATION.md](docs/LOCAL_VERIFICATION.md).

## Совместная работа Claude Code и Codex

Открывайте новую сессию из корня проекта. Общие постоянные инструкции находятся
в [AGENTS.md](AGENTS.md), фактическое состояние исследования и следующий шаг —
в [PROJECT_STATUS.md](PROJECT_STATUS.md). Codex загружает `AGENTS.md`, Claude Code
получает те же инструкции через `@AGENTS.md` в [CLAUDE.md](CLAUDE.md).
Эти способы загрузки описаны в официальной документации
[Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md) и
[Claude Code](https://code.claude.com/docs/en/memory#import-additional-files).

В начале задачи агент читает статус и нужные файлы, после существенных изменений
сам обновляет статус в рамках этой же задачи. Мелкие действия в статус не входят;
результаты, решения, нерешённые вопросы и следующий шаг сохраняются для нового чата.
Математические правила и методология экспериментов остаются в `.claude/`;
ссылки в `AGENTS.md` делают их общими для обоих агентов.
